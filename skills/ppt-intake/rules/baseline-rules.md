# 铁律（Baseline Rules）

违反任何一条都必须返工。这些规则的存在理由只有一个：**用户打开成品时，
看到的必须仍是"自己那份 PPT"，只是内容变全了。**

## R1 · 基准格式绝对优先
- 一切视觉决策以基准 PPT 为准：母版、版式、主题色、字体、字号、页眉页脚、logo。
- 材料里"更好看"的样式**不是**采用它的理由。用户没要求重新设计，就是在要求整合。
- 如果某条材料内容在基准里找不到能承载它的版式，选最接近的同角色页克隆，
  并在变更说明中明确指出局限（参考官方 pptx skill 的 template-inheritance 原则）。

## R2 · 新页只能"克隆 + 填充"，禁止从零新建
- 新增页 = `clone_slide(base, 同角色页)` + 按 merge plan 替换文本。
- 禁止 `prs.slides.add_slide(blank_layout)` 后手摆文本框 —— 新页会立刻露馅
  （字体、间距、对齐与基准页不一致）。
- 禁止把材料页直接复制进基准文件 —— 会带入外来的 layout/master/theme part、
  嵌套主题色和字体，污染整个文件。

## R3 · 原件只读
- 基准 PPT 和材料 PPT 永远保持字节不变。
- 输出永远写到新文件（默认 `<stem>_merged.pptx`，与基准同目录）。
- `merge_apply.py` 内部就是"先复制再改"，但你也不要把输出路径指到任何输入文件上。

## R4 · 文本预算（防溢出的唯一可靠手段）
- 每个被替换文本框的预算 = `orig_len × 1.1`（inspect 清单里已算好 `budget` 字段）。
- **label 角色**（h<1.5cm 或 orig_len≤8 或 字号≥20pt）：只放短语，硬上限 `max(orig_len, 8)`。
- **body 角色**：超预算就删字，不缩字号（缩字号破坏排版节奏，是最后手段）。
- 克隆页的替换同样受限：新文案逐框对照**被克隆页原文本**的 budget。

## R5 · 内容取舍要留痕
- 每个材料页的去向必须是四选一：`update`(并入现有页) / `append`(克隆新增页) /
  `drop`(丢弃) / `conflict`(标记冲突)。
- drop 必须写理由（重复/过时/与本 PPT 目标无关）；conflict 必须在变更说明中
  列出两边的值并说明你采用了哪个、为什么。拿不准 → conflict，不要默默选择。

## R6 · 语义合并优于物理搬运
- 材料 3 页讲的事若基准 1 页能承载 → 合并成 1 页的更新，而不是克隆 3 页。
- 材料的图表数据若很关键：优先把**数字**整合进基准现有数据页文案；
  只有当图表本身不可替代时才考虑图片导入（见 merge plan 的 `import_image`）。

## R7 · 未涉及的页保持原样
- merge plan 没碰到的页，其文本内容必须与基准逐字一致（validate 第 8 项会查）。
- 换句话说：计划写得多"小"，改动就多"小"。能为一次 replace_text 解决的，
  不要顺手"优化"别的页。

## R8 · 交付前必须过验证
- `validate_output.py` 全绿（重开文件、rels 完整、无占位符残留、无超预算、页序符合计划）。
- 交付物 = pptx + `变更说明.md`（update/append/drop/conflict 四类清单 + 理由）。
